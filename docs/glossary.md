# Глоссарий

| Термин | Значение |
|---|---|
| **ПД** (`PD`) | Проектная документация, стадия «П». Состав задан ПП РФ № 87, проходит госэкспертизу |
| **РД** (`RD`) | Рабочая документация, стадия «Р». Чертежи и спецификации для производства работ (ГОСТ Р 21.101-2020) |
| **ИД** (`ID`) | Исполнительная документация: акты, журналы, исполнительные схемы, РД со штампами (Приказ Минстроя № 344/пр) |
| **ГСН** | Государственный строительный надзор. Инспектор ГСН — пользователь нашей системы |
| **ИАИС «РиН»** | Интегрированная автоматизированная информационная система «Разрешения и нарушения» (Москва), целевая внешняя ИС |
| **Объект** (`object`) | Объект капитального строительства: здание или сооружение. Разбиение датасетов делается по объектам |
| **Проверка** (`process`, `process_id`) | Один цикл сверки документов объекта: загрузка → парсинг → протокол → верификация → финализация |
| **Раздел** (`section`) | Раздел ПД по ПП 87: ПЗ, СПЗУ, АР, КР, ИОС1–5, ТХ, ПОС, ООС, ППМ, БЭ, ОДИ, СМ, ИН |
| **Марка** (`discipline`) | Марка основного комплекта РД: АР, КЖ, КМ, КР, ЭОМ, ВК, ОВ, СС, ГП… В API поле `discipline` хранит и раздел ПД, и марку РД |
| **Шифр** (`document_code`) | Обозначение документа, например `25-01-АР-ПЭ`. Ключевое поле: Exact Match ≥ 0.90 |
| **Редакция / изменение** (`revision`) | Номер изменения документа (графа «Изм.» основной надписи). Сравниваем **последнюю утверждённую** редакцию |
| **Статус утверждения** (`approval_status`) | Утверждён ли документ (штамп «В производство работ», согласование). Без утверждения эталоном быть не может |
| **Основная надпись / штамп** (`title_block`) | Таблица в правом нижнем углу листа по ГОСТ Р 21.101: шифр, наименование, стадия, лист, листов, изм., подписи, даты |
| **Лист** (`sheet`) | Номер листа по штампу. Может не совпадать с номером страницы PDF (`page`) |
| **ОД** | Общие данные — первые листы комплекта РД: ведомости, ТЭП, перечень скрытых работ |
| **ТЭП** | Технико-экономические показатели: площади, объёмы, этажность |
| **Спецификация** (СО) | Табличный перечень оборудования, изделий и материалов (ГОСТ 21.110) |
| **Ведомость** (ВО, ВС, ВР…) | Табличные перечни: рабочих чертежей, ссылочных документов, заполнения проёмов и др. |
| **АОСР** | Акт освидетельствования скрытых работ — ключевой документ ИД |
| **ОЖР** | Общий журнал работ |
| **КС-2, КС-3** | Акт о приёмке выполненных работ и справка о стоимости (ИД для раздела СМ) |
| **СП, ГОСТ, ФЗ** | Своды правил, стандарты, федеральные законы — нормативные ссылки параметров |
| **УКЭП** | Усиленная квалифицированная электронная подпись |
| **Матрица контроля** | 132 контролируемых параметра M-001…M-132 (таблица `params`, Приложение 1 ТЗ) |
| **Параметр** (`param`, `param_code`) | Строка матрицы, например `M-055` «Класс прочности бетона монолитных конструкций» |
| **Реестр файлов** (`registry`, `UploadManifest`) | Обязательный машиночитаемый перечень файлов комплекта (CSV/XLSX/JSON): `file_id`, sha256, стадия, шифр, редакция, `approval_status`, связи редакций. Без него комплект — `CLARIFICATION_REQUIRED`. См. [domain/registry.md](domain/registry.md) |
| **Триггер** (`trigger_logic`) | Условие, при котором расхождение становится кандидатом: «< 0.9 м», «Расхождение > 0», «Понижение класса» |
| **Атомарное правило** (`rule_key`) | Конкретный экземпляр проверки внутри параметра: дверь Д-3, помещение 105, плита П-2 |
| **Finding** | Результат проверки одного атомарного правила — строка таблицы `checks` со статусом |
| **Кандидат** (`CANDIDATE`) | Найденное моделью предварительное расхождение, ждёт решения инспектора |
| **Подтверждённое нарушение** (`CONFIRMED_VIOLATION`) | Кандидат, подтверждённый инспектором. Модель этот статус не ставит **никогда** |
| **Проверенный отрицательный** (`NEGATIVE_VERIFIED`) | Сопоставимые источники проверены, расхождения нет (или кандидат отклонён инспектором). Отрицательный пример для обучения |
| **Гипотеза** (`SUSPICION`) | Подозрение из свободного поиска вне матрицы. Не считается нарушением |
| **Evidence group** (доказательная группа) | Единица результата и разметки: объект + параметр/правило + актуальные ПД/РД/ИД + фрагменты с координатами |
| **Evidence fragment** (доказательный фрагмент) | Место в документе: `file_id`, `sha256`, страница, `bbox`, извлечённое значение, роль (EXPECTED / ACTUAL) |
| **Карточка доказательства** | Всё, что инспектор видит по кандидату (REQ-CMP-09) |
| **bbox** | Прямоугольник `[x0, y0, x1, y1]` в долях видимой страницы, начало координат в левом верхнем углу |
| **CropBox / MediaBox / Rotate** | Параметры страницы PDF: видимая область, физический размер, поворот. Учитываются при нормализации bbox |
| **Сценарий** (`scenario`) | Какие стадии загружены: FULL, PD_RD_ONLY, PD_ID_ONLY, RD_ID_ONLY, SINGLE_ONLY, PARTIALLY_LOADED |
| **Дозагрузка** | Добавление файлов в существующую проверку до финализации с инкрементальным пересчётом |
| **Финализация** | Кнопка «Завершить». После неё протокол неизменен и передаётся в РиН |
| **GOLD** | Эталонный размеченный набор. Позитивы — `CONFIRMED_VIOLATION`, негативы — `NEGATIVE_VERIFIED` |
| **Куратор данных** | Эксперт, одобряющий записи GOLD перед включением в `dataset_version`. В системе это роль `ML_ENGINEER` |
| **matrix_version / model_version / dataset_version** | Версии матрицы, модели и набора данных, фиксируемые в каждом протоколе |
| **input_manifest_hash** | SHA-256 от отсортированного списка SHA-256 входных файлов проверки |
| **CER / WER** | Character / Word Error Rate — метрики OCR. Character Accuracy = 1 − CER |
| **Exact Match** (EM) | Доля полностью совпавших значений ключевых полей после нормализации |
| **IoU** | Intersection over Union — перекрытие bbox с эталоном. Порог ≥ 0.5 |
| **FPR** | False Positive Rate — доля ложных срабатываний на отрицательных группах |
| **LOW_QUALITY / ABSTAIN** | Качество распознавания низкое / система отказывается распознавать зону (рукопись, нечитаемо) |
