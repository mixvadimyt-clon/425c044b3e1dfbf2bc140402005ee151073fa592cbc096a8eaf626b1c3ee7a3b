# Реестр файлов комплекта

> Источник: «Перечень исполнительной документации» ред. 1.1 от организаторов (папка `ТЗ/` основного клона, в git не лежит).
> Контракт: `UploadManifest` / `ManifestFile` / `CompletenessSummary` / `RegistryIssue`, версия 0.4.

**Реестр обязателен.** Каждый загружаемый комплект сопровождается машиночитаемым реестром CSV, XLSX или JSON. Без реестра комплект **принимается**, анализ идёт, но статус полноты — `CLARIFICATION_REQUIRED`: система не вправе утверждать, какие редакции актуальны и всё ли загружено.

## Как передать

| Путь | Как |
|---|---|
| Загрузка через интерфейс | `POST /api/v1/documents/upload`, поле `registry` (файл) или `manifest` (JSON-строка) |
| Реестр после загрузки / замена реестра | `POST /api/v1/processes/{id}/registry` (multipart: `registry` или `manifest`). Запускает новое сравнение → новая версия протокола (`trigger = METADATA_CHANGE`) |
| Серверный импорт папки | `POST /api/v1/documents/import`: `registry_path` или автопоиск в корне папки по имени `registry.*`, `реестр*`, `manifest*`, `перечень*` (CSV/XLSX/JSON). Файл реестра документом не считается |
| CLI | `npm run import:dir -- --path "..." --manifest manifest.json` |

При дозагрузке без нового реестра действует последний загруженный. Новый реестр, пришедший вместе с дозагрузкой, относится ко всему комплекту: с ним сопоставляются и ранее загруженные файлы. Все загруженные реестры хранятся (`registries`, файл — `var/storage/registries/{sha256}`).

## Колонки

Регистр, пробелы и знаки в заголовках не важны. Строка заголовка может стоять не первой (ищется в первых 10 строках). Разделитель CSV определяется сам: `;`, табуляция или `,`.

| Поле (контракт) | Русские заголовки | Значения |
|---|---|---|
| `object_id` | Идентификатор объекта, Надзорное дело | стабильный id объекта/дела. Если у всех строк один — это `object_external_id` |
| `file_id` | Идентификатор файла, ID файла | id заказчика, например `ALT79B-000015`. **Перезапись под тем же `file_id` запрещена** |
| `file_name` | Имя файла, Исходное имя, Файл | имя при загрузке; при импорте можно путь относительно папки |
| `sha256` | SHA-256, Хеш, Контрольная сумма | 64 hex-символа, сверяется с фактическим файлом |
| `doc_stage` | Стадия | `PD`/`RD`/`ID` или `ПД`/`РД`/`ИД` |
| `discipline` | Раздел, Марка | АР, КР, КЖ, ОВ, ВК… |
| `document_code` | Шифр, Шифр документа | без сокращений |
| `revision` | Редакция, Изменение, Изм. | номер или обозначение |
| `approval_status` | Статус утверждения, Статус | `DRAFT`, `APPROVED`, `FOR_CONSTRUCTION`, `SUPERSEDED`, `CANCELLED`; по-русски: черновик, утверждена, в производство работ, заменена, аннулирована |
| `approval_date` | Дата утверждения, Дата выдачи | `ГГГГ-ММ-ДД`, `ДД.ММ.ГГГГ` или дата Excel |
| `sheet_page_range` | Диапазон листов, Листы, Страницы | «1-56» или «Л1=с3; Л2=с4» |
| `predecessor_id` / `successor_id` | Предшественник, Заменяет / Преемник, Заменена на | `file_id` связанной редакции |
| `predecessor_file_name` | — | если `file_id` в реестре нет |
| `signature_status` | Подпись, Статус подписи, УКЭП | `SIGNED` (есть, да), `QES` (УКЭП, ЭП), `ABSENT` (нет), `NOT_REQUIRED`, иначе `UNKNOWN` |
| `title` | Наименование | — |

Нужен хотя бы `file_name` или `sha256`. Ошибки значений возвращаются одним ответом `400 REGISTRY_INVALID` со списком `details.errors` (с номерами строк).

Пример CSV (Excel, русская локаль):

```csv
object_id;file_id;file_name;sha256;doc_stage;discipline;document_code;revision;approval_status;approval_date;sheet_page_range;predecessor_id;successor_id;signature_status
ALT79B;ALT79B-000015;3. П-2025-04-266-АР Изм. 1.pdf;…;PD;АР;П-2025-04.266-АР;1;APPROVED;27.04.2026;1-56;ALT79B-000014;;SIGNED
ALT79B;ALT79B-000014;3. Раздел 3 ЖС-РД-270121-П-АР.pdf;…;PD;АР;П-2025-04.266-АР;0;SUPERSEDED;12.02.2025;1-21;;ALT79B-000015;SIGNED
ALT79B;ALT79B-000077;РД-2025-04-266-АР2.pdf;…;RD;АР;РД-2025-04-266-АР2;0;FOR_CONSTRUCTION;11.11.2025;1-26;;;QES
```

JSON — объект `UploadManifest` (`files[]`, `expected[]`, `object_external_id`) или просто массив строк.

## Манифест организаторов и архивы

- **JSONL.** Реестр можно передать в формате `document_manifest.jsonl` организаторов — по объекту на строку. Понимаются их колонки: `relative_path` / `source_relative_path` → `file_name`, `stage` → `doc_stage`, `section` → `discipline`, `source_sha256` → `sha256`. Лишние поля (`pdf_pages`, `duplicate_group`) игнорируются. При серверном импорте файл `document_manifest.*` в корне папки находится сам.
- **`.zip` при серверном импорте** распаковывается: содержимое — отдельные файлы с путём «архив/файл» (так их и указывает реестр). Имена в архивах из Windows (CP866) декодируются. Сам архив остаётся в комплекте карточкой.
- **Форматы без анализа** (`.7z`, `.rar`, `.dwg`, изображения и т.п.; у организаторов `FORMAT_CARD_ONLY`) при серверном импорте принимаются **карточкой**: формат `OTHER`, статус `SKIPPED`, в ML не уходят. Строка реестра считается закрытой, замечание `FORMAT_CARD_ONLY` полноту не блокирует. Через интерфейс такие файлы по-прежнему отклоняются (REQ-UPL-02).

## Сопоставление и приём

1. Строка реестра для файла: по имени и `sha256` вместе → по `sha256` → по пути при импорте → по `file_name`. Контрольная сумма важнее имени: одинаково названные файлы разных стадий («Общие данные.pdf» в ПД и РД) занимают каждый свою строку. Совпадение только по имени при другой сумме — замечание `SHA256_MISMATCH`.
2. Поля реестра важнее оценки по имени файла и ML (`metadata_source = MANIFEST`). ML всё равно извлекает свои метаданные — они лежат в `metadata` и нужны для сверки.
3. `file_id` уже занят в объекте файлом с другим содержимым → файл отклоняется `FILE_ID_CONFLICT` (при загрузке реестра в готовую проверку — `409`).
4. **Повторная загрузка** того же содержимого в ту же проверку создаёт новую запись (`duplicate_of` → первый экземпляр) и новую версию протокола, но в сравнение идёт только первый экземпляр.
5. Связи редакций: `predecessor_id`/`successor_id` → `files.predecessor_id`. Связи строятся заново по действующему реестру, так что исправленный реестр снимает ошибочную связь. Ручной выбор инспектора (`PATCH /files/{id}` с основанием) не перетирается.
6. Файл, выпавший из нового реестра, теряет поля реестра и возвращается к подсказке пользователя или стадии по папке импорта (`files.base_stage_hint`), к оценке ML или по имени файла.

## Какие файлы идут в эталонное сравнение

| Ситуация | Результат |
|---|---|
| Одна применимая утверждённая редакция (`APPROVED` или `FOR_CONSTRUCTION`) | Эталон; в доказательствах фиксируются `file_id` и SHA-256 |
| Новая редакция явно заменяет старую (`successor`, `SUPERSEDED`) | Старая хранится для аудита, `excluded_from_comparison = true`, в `CompareRequest.excluded_files` |
| `CANCELLED` | Исключается так же |
| Инспектор отметил редакцию авторитетной | Важнее статуса из реестра |
| Несколько действующих редакций одного шифра без однозначного статуса | `AMBIGUOUS_REVISION` → `CLARIFICATION_REQUIRED`; вывод о нарушении блокирует движок сравнения до выбора инспектора |
| Обязательного файла нет | `MISSING_FILE` → `MISSING_EVIDENCE`, нарушением не считается |
| Файл нечитаем | `UNREADABLE_FILE` → `NOT_COMPARABLE`, нужна замена |

**В движке сравнения** (`services/ml/src/inspector_ml/compare/revisions.py`) — те же правила, что у api в расчёте полноты (`stages.ts::ambiguousRevisions`), поэтому замечание комплекта и статус проверки не расходятся:

- редакция, на которую другая ссылается как на предыдущую, или у которой указана следующая, в сравнение не идёт («Заменена редакцией «…»») — если инспектор не выбрал её сам;
- редакции группируются по стадии и шифру (регистр, пробелы и «_» в шифре не различаются). В группе однозначно, если инспектор отметил ровно одну или утверждена ровно одна (`APPROVED` / `FOR_CONSTRUCTION`); остальные — `SUPERSEDED` в `file_resolution` с причиной;
- иначе все редакции группы — `CONFLICT`: значения из них извлекаются (доказательства видны инспектору), но точка получает `CLARIFICATION_REQUIRED` «Вывод о нарушении заблокирован: несколько редакций «шифр» (РД) без однозначного выбора: …». Конфликт в одном документе не блокирует параметры, значения которых взяты из других;
- номер изменения и дата утверждения выбор не решают — так же, как в api, чтобы не выбирать молча.

## Статус полноты комплекта

`ProcessInfo.completeness.status` — худший из:

1. `CLARIFICATION_REQUIRED` — нет реестра (`NO_REGISTRY`), файл вне реестра (`NOT_IN_REGISTRY`), не совпал хеш (`SHA256_MISMATCH`), неоднозначные редакции (`AMBIGUOUS_REVISION`);
2. `NOT_COMPARABLE` — есть нечитаемые файлы;
3. `MISSING_EVIDENCE` — не загружены файлы из реестра или ожидаемые документы (`expected[]`);
4. `COMPLETE`.

`DUPLICATE_CONTENT` и `UNKNOWN_LINK` — информационные, статус не ухудшают. Все замечания — в `completeness.issues[]` с `file_id`, `external_file_id`, `file_name`: интерфейс показывает их списком со ссылками на файлы и кнопкой «Загрузить реестр».

Статусы стадий (`PD_UPLOADED` и т.д.) — [statuses.md §2](statuses.md): строки реестра входят в ожидаемый состав своей стадии.
