## Формат CSV

UTF-8, разделитель — запятая, значения с запятыми берутся в кавычки. Списки внутри ячейки разделяются `|`.

| Колонка | Тип | Смысл и как использовать |
|---|---|---|
| `code` | str ≤ 20 | Код параметра из Приложения 1: `M-055` |
| `external_code` | str ≤ 20 | Код параметра у организаторов (каталог `parameter_catalog_132` в датасете): `KR-055`. Выводится из раздела и номера (`build_params.py`), сверяется с `data/samples/parameter-code-map.csv`. Нужен для выгрузки `submission` |
| `section` | str ≤ 50 | Раздел матрицы: ПЗ, СПЗУ, АР, КР, ИОС1–5, ПОС, ПОД, ООС, ППМ, ОДИ, ЗУ, СМ |
| `parameter_name` | str | Наименование |
| `unit` | str | Единица: м², м³, мм, шт., Марка, Класс |
| `source_pd` / `source_rd` / `source_id` | text | **Где искать** значение в ПД, РД и ИД: лист, таблица. Пустое поле означает, что стадия для параметра не нужна (парное сравнение) |
| `trigger_logic` | text | Когда расхождение становится кандидатом. Разбирается в правило, см. ниже |
| `review_priority` | HIGH / MEDIUM / LOW | Очерёдность проверки |
| `sp_reference`, `gost_reference`, `fz_reference`, `other_normative` | text | Нормативные ссылки для обоснования |
| `data_type` | number / string / boolean / coordinate / enum | Как сравнивать. Без строки в overrides выводится по единице: м², мм, шт. → `number`; Марка, Класс, Степень → `enum`; «—», «Статус» и составные («шт. / м²») → `string` |
| `min_value`, `max_value` | float | Нормативные пороги: значение вне диапазона даёт кандидата |
| `regex_pattern` | str ≤ 255 | Регулярное выражение для извлечения в синтаксисе **Python `re`** (исполняет ML). Группа 1 — значение. Inline-флаги вроде `(?i)` допустимы |
| `semantic_anchors` | list | *Расширение.* Фразы-якоря для семантического поиска (Sentence-BERT) |
| `enum_values` | list | *Расширение.* Упорядоченный по возрастанию список значений для `enum`: так работает правило «понижение класса» |
| `is_active` | bool | Неактивные параметры не проверяются |

## Как обновить матрицу в работающей базе

`npm run db:reset` пересоздаёт базу целиком — во время экспертизы это потеря всех проверок.
Для работающей базы есть импорт:

```bash
cd services/api
npm run matrix:import                                   # план: что изменится, ничего не пишет
npm run matrix:import -- --apply
npm run matrix:import -- --file новая-матрица.csv --apply
npm run matrix:import -- --activate M-010,M-011 --apply
npm run matrix:import -- --activate all --apply     # вся матрица
```

На стенде — внутри контейнера api, база лежит в его томе:

```bash
docker compose -f docker-compose.app.yml --env-file .env.stand exec api   node --disable-warning=ExperimentalWarning dist/cli/matrix-import.js --apply
```

Правила, из которых он исходит:

- **активность из файла не берётся.** В `params.csv` у всех 132 параметров `is_active=false`,
  а работают M-002 и M-055: импорт «как в файле» выключил бы проверку целиком. Активность меняется
  только явными `--activate` / `--deactivate`;
- **новый параметр приходит выключенным.** Включённый параметр — это новые кандидаты в работе
  у инспектора, молча такое не включают;
- **всё или ничего.** Ошибка хотя бы в одной строке (код не по формату, повтор, пустое
  наименование, чужой тип или приоритет, `min > max`) — не пишется ничего;
- **параметры, которых нет в файле, остаются в базе.** На них ссылаются готовые протоколы,
  а «пропал из файла» не равно «отменён»;
- **версия матрицы** создаётся в той же транзакции и только при реальных изменениях;
- **шаблоны проверяются мягко.** `regex_pattern` написан в синтаксисе Python (`(?i)` в начале),
  и если его не понимает движок JS — это замечание, а не ошибка: исполняет его ML.

Перезапускать api не нужно: активные параметры он читает из базы при каждом запуске сравнения.

## Правила по умолчанию и выбор значения по разделу

До 24.09 шаблон или якоря были у 10 параметров из 132, остальным общему разбору (`extract/regex.py`)
было не за что взяться. Теперь `build_params.py` даёт правило каждому параметру без своего — из его названия:

- **число** — якорь = название (строка таблицы «название | ед. | значение», берётся самое правое число
  строки) и шаблон «название …: 12,5» по тексту;
- **текст, перечисление, координаты** — шаблон «название: значение;» до точки с запятой. После
  названия допускаются уточнение в скобках и закрывающая скобка или кавычка: «Мероприятия по
  инженерной подготовке (дренажи): …»;
- «е» и «ё» в названии не различаются, слова разделяются любыми знаками.

Это минимум, а не проверенное на живых документах извлечение: в реальных ТЭП строки называются
по-разному. Синонимы для ходовых параметров дописываются в `overrides.csv` (якоря через `|`) и
**дополняют** название, а не заменяют его: формулировка матрицы остаётся якорем всегда. Синонимы
из живых документов есть у 11 параметров ПЗ и СПЗУ — «количество этажей», «строительный
объем», «кол-во машиномест в подземной автостоянке», «процент застройки», «площадь озеленения» и т.д.

Якорь сравнивается со строкой таблицы подстрокой или в другой форме слов (только в коротком
наименовании), поэтому короткие и двусмысленные формулировки не берём: «количество машино-мест»
ловит строку «… для МГН» (другой параметр), «вместимость» — ёмкость резервуара в ООС, «спортивные
площадки» — ограждение площадки, «тротуарной плитки» — состав покрытия, «высота объекта» — «абсолютная
высота объекта капитального строительства» (отметка над уровнем моря). У M-008 вместо якоря шаблон,
который не видит абсолютную и пожарно-техническую высоту; у M-021 и M-124 шаблон берёт только
«класс» и «классе энергетической эффективности» — «с классом энергоэффективности А+» пишут про
бытовую технику. Свои правила сейчас у M-001…M-003, M-008, M-015, M-021…M-023, M-041, M-124;
`enum_values` — ещё у M-050, M-056, M-057, M-107.

**Свои извлекатели ML** (`extract/api.py`) — у M-002 (экспликации), M-009 (абсолютная отметка
0,000), M-055 (класс бетона) и M-058 (толщина фундаментной плиты / ростверка): шаблон и якоря матрицы
у них не используются. Они читают фразу, как её пишут в настоящих ПЗ и КР, и отсекают неправдоподобное

## Семантика `trigger_logic`

Движок сравнения разбирает свободный текст триггера («Логика ИИ-связи (предварительный триггер)» Приложения 1) в правило срабатывания — `services/ml/src/inspector_ml/compare/triggers.py`. Эталон — ПД: значения РД и ИД сравниваются с ним. Кандидат появляется, **только если отличие описано триггером**. Различие, которое триггер не описывает, даёт `NEGATIVE_VERIFIED` с объяснением — как `KR-058` в эталоне организаторов («различие не триггерное»).

| Что в тексте | Правило | Пример |
|---|---|---|
| «Понижение», «Снижение», «Уменьшение», «Сокращение», «Занижение», «Сужение», «Ухудшение», «Подмена», «Замена», «Отсутствие», «Исключение» | срабатывает только уменьшение; для `enum` — шаг вниз по `enum_values` (шкала по возрастанию «лучше») | M-055 (B35 → B30), M-058, M-015, M-022 |
| «Увеличение», «Превышение», «Завышение», «с более высоким …» | срабатывает только рост | M-008, M-017, M-126 |
| «Изменение», «Расхождение», «Дельта», «Несоответствие», «Несовпадение», «Смещение», «Нарушение», «Выход», «… или …» в обе стороны | любое отличие | M-004, M-009, M-025, M-068 |
| `> N%` | относительное отклонение от ПД больше `N` % (строго) | M-002 — «Дельта … > 1%», M-024, M-132 |
| `> N` после «Расхождение / Дельта / Смещение» | абсолютное отклонение больше `N` (`> 0` — любое после нормализации) | M-001, M-034 (`> 0.5 м`) |
| `< X`, «менее X», «ниже X»; `> X` без слова об изменении | **предел из матрицы:** значение РД/ИД меньше (больше) `X` — кандидат, даже если в ПД значения нет. Диапазон «1.5–1.8 м» — нижняя граница, несколько пределов («< 2.0 м или < 1.9 м») — наименьший. Нормы сами по себе не проверяем — только записанный в матрице порог | M-041 (`< 0.9 м`), M-040, M-118 (`> 0.014 м`), M-038 (`< 10%`) |
| `min_value` / `max_value` матрицы | такие же пределы, если в тексте своих нет | — |

Слова в скобках и кавычках направление не меняют: «Увеличение высоты (риск нарушения …)» — только рост, «отсутствие табло "Выход"» — только уменьшение.

**Нормализация перед сравнением:**

- **числа:** «3 009,4» = 3009.4; совпадение с точностью округления (половина младшего разряда более грубой записи: 1234,5 и 1234,46 совпадают, 1234,5 и 1234,4 — нет); единицы длины порога переводятся в единицы значения (м ↔ мм ↔ см);
- **перечисления:** кириллица-двойник → латиница, без пробелов («В 22,5» = «B22.5»); число без буквы («класс 30») сопоставляется с единственным значением перечня. Значение не из перечня (марка «М300» вместо класса) — `NOT_COMPARABLE`, не угадываем;
- **строки:** регистр, пробелы, «ё» и точка в конце не различаются. Любое другое отличие — кандидат: назначение помещения у M-002 — отдельная точка «пом. 1.09 (назначение)»;
- **да/нет** («есть», «отсутствует», «предусмотрено»…) — с учётом направления;
- **координаты** — евклидово смещение против абсолютного порога.

**Атомарные точки ПД ↔ РД ↔ ИД** сопоставляются по нормализованному `rule_key`: «Помещение 1-09», «ПОМ 1,09» и «пом. 1.09» — одна точка (регистр, «пом.», разделитель в номере). В протокол и в `location` выгрузки идёт подпись из ПД.

**Что не разбирается.** У числовых и перечислимых параметров — только M-065, M-097, M-114: качественные условия без величины («Самовольная заделка проёмов», «Складирование на бровке», «Радиус ПГ не покрывает»). Их точки получают `NOT_COMPARABLE` с причиной «триггер матрицы не разобран: «…»» — это покрыто тестом на всех 132 триггерах. Строковые параметры с такими триггерами сравниваются как текст.

В `rationale` кандидата — значения стадий, вердикт («отклонение 1.35 % больше порога 1 %») и текст триггера. В `delta` — «+40.7 (+1.35 %)» или «понижение на 1 ступ.». В `normative_reference` — СП, ГОСТ, ФЗ и прочие нормативы параметра из матрицы.

**Атомарные правила (`rule_key`):**

- M-002 — итог по зданию («Общая площадь здания») и **итог по каждому этажу / помещению экспликации** («Экспликация помещений 1-го этажа», «пом. 1.09»).
