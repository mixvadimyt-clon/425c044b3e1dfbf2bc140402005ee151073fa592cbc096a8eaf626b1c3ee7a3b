# 0006. Стек ML-конвейера
- Статус: принято
- Дата: 2026-09-17
- Автор: Команда

## Контекст
Для конвейера сверки нужен набор технологий. Документы датасета — векторные PDF с текстовым слоем (проверено на выборке), но в полном наборе будут и сканы.

## Решение
| Этап | Технология |
|---|---|
| Загрузка документов | PyMuPDF |
| Классификатор качества страницы | custom Python |
| Резервный OCR | PaddleOCR |
| Макет / таблицы | Docling + custom extraction |
| Структурированное извлечение | Qwen через vLLM (OpenAI-совместимый API; локально — Ollama) |
| Сопоставление сущностей | правила, эмбеддинги — позже |
| Совмещение чертежей | OpenCV ORB + RANSAC + homography |
| Визуальные различия | OpenCV absdiff / contours |
| Движок правил | Python |
| Объяснение | Qwen через vLLM |
| Доказательство | page + bbox + source + hash |
| Решение инспектора | CONFIRM / REJECT / CLARIFY |

- LLM вызывается через OpenAI-совместимый клиент с `LLM_BASE_URL`, поэтому vLLM (сервер с GPU) и Ollama (ноутбук) взаимозаменяемы. `LLM_ENABLED=false` по умолчанию — конвейер обязан работать без LLM.
- Тяжёлые зависимости (PaddleOCR, Docling, sentence-transformers) — необязательные extras в `pyproject.toml`.
- Результат визуального сравнения передаётся в api как `page_pairs` (контракт v0.2) и показывается на экране «Сравнение PDF-схем».
- Tesseract, упомянутый в v0.1, остаётся запасным OCR.

## Лицензии и размер моделей
Модели и библиотеки должны быть с открытыми весами и лицензией, допускающей коммерческое и государственное использование. Сверхбольшие модели не нужны, квантизация — плюс.

**Уточнение 2026-09-21: ориентир — H100 80 ГБ, и карту можно делить.** Проверяющий стенд — **один NVIDIA H100 80 ГБ**, и на одном GPU могут одновременно работать несколько контуров. Отсюда:

- модель выбираем под **80 ГБ за вычетом OCR и контекста**: Qwen 32B-класса в квантизации, а не в bf16 «под потолок». Модель, которая помещается только при монопольном владении картой, нам не подходит — рядом может считать чужой контур;
- **потребление видеопамяти ограничиваем явно** и у OCR, и у LLM: значения по умолчанию в PaddlePaddle и vLLM рассчитаны на монопольную карту;
- путь без LLM и небольшие квантизованные модели остаются для локальной разработки на ноутбуках и для нашего публичного стенда без GPU (ADR-0007).

## Последствия
- Базовый путь (PyMuPDF + regex/таблицы + правила) даёт результат на выборке уже сейчас; LLM и OCR добавляют покрытие.
- Ответы LLM всегда проверяются правилами и привязываются к bbox — без доказательства вывод не попадает в кандидаты.
