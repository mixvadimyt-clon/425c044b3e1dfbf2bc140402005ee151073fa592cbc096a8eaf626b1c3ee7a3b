# 0001. Contract-first: OpenAPI 3.0 и схемы событий в `contracts/`
- Статус: принято
- Дата: 2026-09-16
- Автор: Команда

## Контекст
Три сервиса пишутся параллельно. ТЗ требует REST+JSON «с обязательной валидацией схемы OpenAPI 3.0» (REQ-STK-05) и RabbitMQ между модулями.

## Решение
- Все межсервисные контракты — в `contracts/`: REST (`openapi/inspector-api.v1.yaml`) и сообщения очереди (`events/ml-events.v1.yaml`, тоже в диалекте OpenAPI 3.0, только `components`).
- Типы в сервисах только генерируются (openapi-typescript, datamodel-code-generator); api роутит и валидирует запросы прямо по спецификации (fastify-openapi-glue).
- Бандлы `contracts/dist/*.json` коммитятся, чтобы ML/FE не нуждались в Node-тулинге.

## Последствия
- Фронт работает против Prism-мока с первого дня; ML тестирует сообщения до готовности api.
- Любое изменение контракта — отдельный PR и перегенерация типов у всех.
