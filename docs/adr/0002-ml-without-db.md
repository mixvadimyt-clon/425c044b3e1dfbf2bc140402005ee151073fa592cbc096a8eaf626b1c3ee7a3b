# 0002. ML-сервис не обращается к базе данных
- Статус: принято
- Дата: 2026-09-16
- Автор: Команда

## Контекст
Схема БД (16+ таблиц) будет активно меняться. Если в неё будут писать и Node, и Python, возникнет два источника миграций и постоянные конфликты между треками.

## Решение
- PostgreSQL знает только `services/api` (Prisma-миграции).
- ML получает всё необходимое в сообщениях (HTTP-задачи или RabbitMQ, см. ADR-0005) (`ParseRequest`, `CompareRequest` — включая снимок матрицы, правил, нормативов, метаданные файлов) и возвращает результаты сообщениями; крупные артефакты (parsed JSON) — в S3.
- ML использует только свой кеш (локально — папка `var/cache`, опционально Redis).

## Последствия
- Воркеры ML stateless, масштабируются репликами.
- `CompareRequest` может быть крупным (132 параметра + реестр файлов) — это приемлемо (десятки–сотни КБ).
- Офлайн-оценка в ML не требует БД: `inspector-ml eval` собирает `CompareRequest` из файлов.
