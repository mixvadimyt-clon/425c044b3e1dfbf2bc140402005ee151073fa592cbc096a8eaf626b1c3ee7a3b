# 0008. LLM берём в работу: границы, модель, что она не имеет права делать

- Статус: принято
- Дата: 2026-09-21
- Автор: Команда

## Контекст

До сегодня порядок был «сначала правила, потом модели» ([ADR-0003](0003-embedding-model.md)).
Порядок был верным, пока мы не знали двух вещей.

**Первое: разбор публичного эталона 21.09.** Из пятнадцати проверок `public_gold_checks`
**четыре — `FREE-HEATING-001`**, то есть свободный поиск вне матрицы: «в помещении по ПД
предусмотрен отопительный прибор, в РД его нет». Правилами это не берётся никак — в матрице
такого параметра нет и не будет, а сравнивать нужно смысл двух описаний. Ещё шесть проверок —
`IOS4-078/079` про конфигурацию приборов в помещениях, и там смысловое сопоставление тоже
ближе к делу, чем регулярка.

**Второе: проверяющий стенд — H100 80 ГБ.** Раньше мы закладывались на возможное отсутствие
GPU, и тяжёлая модель выглядела роскошью. Теперь она выглядит недоиспользованным ресурсом.

## Решение

### Что LLM делает

1. **Свободный поиск расхождений** между ПД и РД по тексту раздела → `SuspicionResult`
   с методом `SEMANTIC_DISSONANCE`. Это гипотеза для инспектора, а не находка.
2. **Объяснение на человеческом языке** для карточки кандидата: чем расхождение существенно.

### Чего LLM не делает никогда

- **не ставит `CONFIRMED_VIOLATION`** — это решение инспектора (REQ-CMP-05) и запрет для модели
  вообще, независимо от того, насколько она уверена;
- **не меняет статусы проверок матрицы.** Дерево статусов считается правилами; LLM добавляет
  гипотезы рядом, а не вместо;
- **не придумывает значения.** Объяснение строится только по переданным фрагментам. Число,
  которого нет ни в одном фрагменте, — признак выдумки: такое объяснение отбрасывается
  и в протокол не попадает. Это проверяется кодом, а не доверием к модели;
- **не ходит наружу.** Только локальный OpenAI-совместимый адрес; облачные API запрещены
  (152-ФЗ, [ADR-0006](0006-ml-stack.md)).

### Модель и рантайм

Уже заложено в `services/ml/config.py` и менять не будем: OpenAI-совместимый клиент,
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_ENABLED=false` по умолчанию. Значит vLLM на H100 и Ollama
на ноутбуке взаимозаменяемы без правок кода.

- **Модель:** Qwen3 8B в квантизации. Не 32B: карту на проверяющем стенде можно делить с чужим
  контуром, а 8B оставляет место OCR и соседям и грузится быстрее. Если на H100 останется
  запас и время — модель меняется одной переменной окружения, код от этого не зависит.
- **Веса — внутри образа.** Интернета в работе нет; докачивать в рантайме нечего.
- **Бюджет видеопамяти:** vLLM не больше трети карты (`--gpu-memory-utilization 0.35`),
  OCR — 20 ГБ (уже ограничен). Вместе около 48 ГБ из 80.
- **Наш публичный стенд остаётся без LLM:** 2 vCPU не потянут, и это нормально —
  `LLM_ENABLED=false`, гипотез просто нет, остальное работает.

### Деградация обязательна

LLM не ответила, ответила мусором или не запущена — **прогон продолжается без гипотез**.
Ни одна проверка не может упасть из-за модели. Таймаут короткий, ошибка пишется в журнал
и не поднимается выше.

## Последствия

- В протоколе появляются гипотезы, которых правила дать не могли, — и ровно там, где эталон
  показывает баллы (свободный поиск);
- растёт размер GPU-образа на размер весов;
- появляется класс ошибок «модель уверенно говорит неправду». Отсюда запрет на числа вне
  фрагментов и статус гипотезы вместо находки: инспектор видит предположение и решает сам.

## Что это отменяет

Правило «сначала правила, потом модели» из [ADR-0003](0003-embedding-model.md) снято
**для свободного поиска**. Для параметров матрицы оно остаётся: там, где правило работает,
модель не нужна, а её вероятностный ответ хуже детерминированного.
