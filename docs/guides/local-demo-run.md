# Полный локальный прогон — от пустой машины до протокола

> Инструкция для обкатки на своём компьютере: поднять всю систему, загрузить настоящий комплект
> **ПД + РД + ИД** и пройти сценарий инспектора до выгрузки протокола. Публичный стенд в Yandex
> Cloud для этого не нужен — он поднимается отдельно, 25.09, к технической экспертизе.
>
> Проверено 22.09 на рабочей станции Команды: сборка и старт с нуля **8 мин 25 с**, разбор комплекта
> из 78 файлов — **33 мин 28 с** (с предрасчитанным кешем; без него было бы около десяти часов).

## 0. Что нужно

- **Docker** с Compose v2. Под Windows — Docker Desktop.
- **Git Bash** или WSL: `start.sh` написан на bash.
- **`python3`** — только для подготовки выборки (шаг 2).
- Около **20 ГБ** свободного диска под образы и данные, с видеокартой около **40 ГБ** (GPU-образ ML весит около 22 ГБ).

Видеокарта не обязательна. Если она есть и виден NVIDIA Container Toolkit, скрипт сам выберет
GPU-вариант образа: на карте страница распознаётся за 2.4 с против 34.3 с на процессоре.

## 1. Забрать репозиторий

```bash
git clone https://github.com/mixvadimyt-clon/425c044b3e1dfbf2bc140402005ee151073fa592cbc096a8eaf626b1c3ee7a3b.git inspector
cd inspector
```

## 2. Собрать комплект ПД + РД + ИД

Сначала посмотрите, **что увидит сервер** в вашей копии датасета. Стадию он определяет по именам
папок, и это не то же самое, что лежит на диске:

```bash
python3 scripts/demo-set.py /путь/к/датасету
```

Отчёт покажет по каждому объекту, сколько файлов попадёт в ПД, РД и ИД, и отметит `✓` те, где есть
все три стадии. **Берите объект с `✓`** — иначе сценарий будет `PD_RD_ONLY` и третья панель
в интерфейсе останется пустой.

> На живом прогоне 22.09 комплект дал ПД 66, РД 10 и **ИД 0** при том, что папка с исполнительной
> документацией на диске была. Этот отчёт показывает такое сразу.

Дальше — план, потом сборка:

```bash
python3 scripts/demo-set.py /путь/к/датасету --object 14_Алтуфьевское_79Б --out dataset
python3 scripts/demo-set.py /путь/к/датасету --object 14_Алтуфьевское_79Б --out dataset --apply
```

Получится `dataset/<объект>/` с папками стадий и `registry.csv`. **Реестр обязателен:** без него
проверка честно уйдёт в `CLARIFICATION_REQUIRED` — это правильное поведение, но на показе выглядит
как поломка.

По умолчанию берётся 8 файлов на стадию и пропускаются файлы крупнее 60 МБ: комплект остаётся
представительным, а разбор — обозримым по времени. Меняется ключами `--per-stage` и `--max-mb`.

Папка `dataset/` в корне репозитория монтируется в контейнеры только на чтение — класть комплект
удобнее сразу туда.

## 3. Поднять систему

```bash
./start.sh
```

Скрипт сам заводит `.env.stand` со свежими секретами, выбирает вариант образа ML по наличию
видеокарты, собирает, поднимает и проверяет: адрес отвечает, интерфейс отдаётся, вход работает.
В конце печатает адрес и **пароль** — запишите его, он генерируется один раз.

**Первая сборка — 10–25 минут:** в образ кладутся веса распознавания, чтобы в работе не требовался
интернет. Повторный запуск — секунды.

Если 80-й порт занят: `./start.sh --port 8080`.

## 4. Залить кеш разбора — иначе будете ждать часами

Без него сканы исполнительной документации распознаются на процессоре примерно по минуте
на страницу. Архив собирается на машине с видеокартой, его размер около 100 МБ.

```bash
docker compose -f docker-compose.app.yml --env-file .env.stand cp cache.tar.gz ml:/tmp/
docker compose -f docker-compose.app.yml --env-file .env.stand exec ml inspector-ml cache import /tmp/cache.tar.gz
docker compose -f docker-compose.app.yml --env-file .env.stand exec ml inspector-ml cache stats
```

Кеш — это тот же результат, который посчитала бы ваша машина, просто посчитанный заранее
на видеокарте; ключ — sha256 файла и версия разбора. Если версия разбора в коде новее архива,
кеш **не подойдёт**, и это правильно: он обязан содержать то, что посчитал бы текущий код.

## 5. Пройти сценарий

Откройте адрес из вывода `start.sh`. Логины `inspector`, `supervisor`, `admin`, `ml` — пароль общий.

1. **Войти** инспектором → дашборд проектов.
2. **Создать объект**, заполнить реквизиты.
3. **Загрузить комплект** — папку из шага 2 вместе с реестром. Видно: стадия у каждого файла,
   отклонённые файлы с причиной, полнота комплекта.
4. **Статус проверки** обновляется сам. Разбор идёт минуты; с кешем — секунды.
5. **Центр верификации:** слева кандидаты и гипотезы, в центре три панели ПД / РД / ИД с рамками
   доказательств, справа карточка с правилом матрицы, значениями по стадиям и обоснованием.
6. **Решение за 2–3 действия:** «Подтвердить», «Отклонить» (меню из 8 причин), «Уточнить».
7. **Протокол:** пять таблиц, версии, **финализация** и **экспорт** — откройте выгруженный PDF.

### Комплект не проходит через браузер

Лимиты интерфейса — **50 МБ на файл и 200 МБ на пакет**. Полный комплект организаторов в них
не укладывается. Такой грузите с сервера; папка указывается относительно `dataset/`:

```bash
./start.sh import 01_ПАКЕТ_УЧАСТНИКАМ_3_ОБЪЕКТА "Пакет участникам, 3 объекта"
```

Скрипт сам войдёт, отправит запрос и напечатает, сколько файлов принято и сколько отклонено.
Разбор запускается сразу — дальше следите за статусом в интерфейсе.

> **Тот же запрос руками через `curl -d '{"path":"…"}'` в Git Bash не работает.** Кириллица
> из командной строки доходит до `curl.exe` в однобайтовой кодировке Windows; api читает тело
> как UTF-8, каждый испорченный байт разворачивается в три, и длина перестаёт сходиться
> с `Content-Length` — `FST_ERR_CTP_INVALID_CONTENT_LENGTH`. Если curl всё же нужен, положите
> тело в файл (его пишет сам bash, в UTF-8) и отправьте `--data-binary @файл`.

Проверить всё одной командой, без браузера:

```bash
./scripts/stand-smoke.sh http://localhost inspector '<пароль>' файл-ПД.pdf файл-РД.pdf
```

## 6. Чего ожидать — чтобы не пугаться на показе

По результатам прогона 22.09 на пилотном комплекте:

| Что увидите | Почему |
|---|---|
| Много `NOT_COMPARABLE` | ключи помещений в ПД и РД пронумерованы по-разному («пом. 101» и «пом. 1.1») — значения есть с обеих сторон, а сопоставить нечего |
| Сравнённых проверок мало | по-настоящему извлекаются **два** параметра из 132: M-002 и M-055. Остальные включены не будут — параметр без проверенного извлечения даёт ложные срабатывания, а они дороже пропусков |
| Долгий разбор двух-трёх файлов | тяжёлые сканы мимо кеша. Скан, не уложившийся в `ML_JOB_TIMEOUT_S`, снимается: файл в ошибке, остальной комплект идёт дальше (с 23.09) |

**Что показать обязательно:** проверку `M-055` по классу бетона. На пилоте она даёт
`ПД = B15, РД = B25` с объяснением «повышение — триггер срабатывает только на понижение». Это
правильный ответ **и** видно, почему система не считает это нарушением.

**Если нужны кандидаты наверняка — контрольный комплект.** Случайная выборка файлов часто
не содержит ни общей площади, ни класса бетона (например, «П-СП» + «РД-ЭМ» + АОСР), и центр
верификации остаётся пустым — это честный ответ, но на показе выглядит как поломка.
[`scripts/demo-errors-set.py`](../../scripts/demo-errors-set.py) собирает шесть PDF с текстовым
слоем и реестром, где ошибки внесены заранее: площадь в РД на 4,6 % меньше ПД, класс бетона
фундаментной плиты понижен в РД и ИД, плит перекрытия — в ИД; одна конструкция совпадает.
Разбор — секунды и без распознавания, поэтому комплект проходит и на слабой машине:

```bash
docker run --rm -v "$PWD:/w" -w /w --entrypoint /app/services/ml/.venv/bin/python \
  inspector-ml scripts/demo-errors-set.py "dataset/Контрольный комплект"
```

Ожидаемый протокол (проверено на стенде 23.09): сценарий `FULL`, три `CANDIDATE` — M-002
(Δ −4,61 %), M-055 «Фундаментная плита» (B30 → B25), M-055 «Плиты перекрытия» (B25 → B22,5 в ИД),
и `NEGATIVE_VERIFIED` для «Вертикальных конструкций» (B35 = B35). Объект и организации в
комплекте вымышлены — на показе так и говорить: это контрольный пример с внесёнными ошибками.

**Второй комплект** (`--set 2`, школа) показывает то, чего нет в первом: нарушение, найденное
только в исполнительной документации, и все три исхода проверки:

```bash
docker run --rm -v "$PWD:/w" -w /w --entrypoint /app/services/ml/.venv/bin/python   inspector-ml scripts/demo-errors-set.py --set 2 "dataset/Контрольный комплект 2"
```

Ожидаемый протокол (проверено 23.09, разбор 7 с): сценарий `FULL`, в центре верификации шесть точек —

| Точка | ПД → РД / ИД | Статус |
|---|---|---|
| M-002 «Общая площадь здания» | 7 850,0 → РД 7 862,5 (+0,16 %, в допуске) → ИД, технический план, 8 105,3 (+3,25 %) | `CANDIDATE` |
| M-055 «Стены подвала» | B30 → РД B25 | `CANDIDATE` |
| M-055 «Ростверк» | B25 = РД B25 → ИД B20 | `CANDIDATE` |
| M-055 «Лестницы» | B20 → РД B22,5, повышение | `NEGATIVE_VERIFIED` |
| M-055 «Плиты перекрытия» | B25 везде | `NEGATIVE_VERIFIED` |
| M-055 «Вертикальные конструкции» | B30; в РД таблица B30, указания B35 | `CLARIFICATION_REQUIRED` |

Последняя точка — хороший повод показать «Уточнить»: РД противоречит сама себе, и система пишет
«В РД несколько разных значений: B30, B35 — нужен выбор источника», а не выбирает сама.

## 7. Остановить

```bash
./start.sh stop     # данные и настройки остаются
./start.sh logs     # логи api и ml
./start.sh check    # быстрая проверка живости
```

Полностью убрать вместе с данными — `docker compose -f docker-compose.app.yml --env-file .env.stand down -v`.
**Ключ `-v` сносит тома:** базу, файлы и кеш разбора. Без него данные переживут перезапуск.

## Если не собирается

| Симптом | Причина | Что делать |
|---|---|---|
| `compose` обрывается на любой команде | нет `.env.stand` | `./infra/stand/make-env.sh`, дальше `--env-file .env.stand` |
| Порт 80 занят | другой сервис | `./start.sh --port 8080` |
| Сборка падает на загрузке весов OCR | недоступен источник моделей | соберите без прогрева и подмонтируйте веса: [deploy.md](deploy.md#если-сборка-образа-ml-падает-на-загрузке-весов) |
| Сборка падает на `paddlepaddle-gpu`, таймаут к `paddle-whl.cdn.bcebos.com` | индекс PaddlePaddle доступен не из любой сети | `./start.sh --cpu`. Если карта нужна — соберите GPU-образ там, где индекс отвечает |
| `api` перезапускается по кругу | пустой `DEMO_PASSWORD` | причина в логе: `./start.sh logs` |
| ИД ноль файлов | стадия не определилась по имени папки | отчёт из шага 2 покажет, что видит сервер |
| При импорте через curl — `FST_ERR_CTP_INVALID_CONTENT_LENGTH` | кириллица в аргументе curl уходит из Git Bash не в UTF-8 | `./start.sh import ПАПКА` — или тело в файл и `--data-binary @файл` |
| В консоли браузера `POST http://api/v1/… ERR_NAME_NOT_RESOLVED` | образ web старее 22.09: адрес склеивался с лишней косой чертой | `git pull`, затем `./start.sh` — образ пересоберётся |

Обслуживание, переменные, HTTPS и публичный стенд — [deploy.md](deploy.md).
