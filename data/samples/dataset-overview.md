## 0. Где лежит выгрузка (обновлено 2026-09-20)

Выгрузка живёт **на машине Команды и раздаётся по сети только на чтение**. Локальных копий
у ML-трека больше нет: на ноутбуке она занимала 20 ГБ, а нужна целиком только для предрасчёта.

- Windows — `\<сервер>\Datasets` (примонтирована как `Z:`)
- WSL — `/mnt/datasets` (строка в `/etc/fstab`, монтирует systemd)

В коде путь нигде не зашит: он передаётся аргументом (`cache warm`, `cache verify`,
`eval extract`, `dataset scan`), так что переезд ничего не сломал.

**`F0152` вернулся.** При переносе на внешний диск 19.09 он терялся — путь больше 400 символов,
и проводник его не копировал. На шаре он есть: **366 PDF из 366** по манифестам против 365
локально. Дозагружать ничего не нужно.

### Чего стоит ждать от сетевого доступа

Замеры на одном и том же документе — `F0232`, скан ИД, 507 страниц, 628 МБ:

| Что | Локальный диск | WSL через шару |
|---|---:|---:|
| Чтение манифестов | мгновенно | мгновенно |
| Обход корпуса с проверкой каждого файла | секунды | **66 с** |
| Чтение файла целиком | 6 МБ/с | **3.1 МБ/с** |
| Открытие документа в PyMuPDF | 0.2 с | 1.2 с |
| **Разбор документа без OCR** | **3 мс/стр** | **2344 мс/стр** |
| **PDF видно в корпусе** | **366** | **319** |

**Разбор по сети медленнее в семьсот раз.** PyMuPDF читает содержимое страниц лениво, и на скане
каждая страница тянет свой растр по SMB отдельно: те же 507 страниц разбираются за 1.6 секунды
локально и за 19.8 минуты с шары. Пропускная способность тут почти ни при чём — файл целиком
читается всего вдвое медленнее, — дело в множестве мелких чтений.

**Вторая беда: из Linux видно не все файлы.** Предел Linux — 255 байт на **один элемент** пути,
а в выгрузке есть каталог на 287 байт (раздел 10.1 про энергоэффективность). Через 9p такое имя
не передаётся, и обрывается не `stat` отдельного файла, а `scandir` **родительской** папки с
`EIO`. Вместе с ней пропадает весь каталог «Пример нарушений на чертежах/ПД» — **42 документа**.
Обход это переживает (`precompute.pdf_files` пропускает нечитаемый каталог с предупреждением),
но данные всё равно теряются.

**Поэтому прогон по всему корпусу с шары не гоняем.** Корпус (8.2 ГБ) копируется в файловую
систему WSL с Windows, где длинные пути работают через `\\?\`, и предрасчёт идёт локально: и
42 файла на месте, и скорость своя, и сеть с чужой машиной ни на что не влияют. После сборки
архива копия удаляется.

Повседневное — манифесты, `eval extract`, разовые замеры по отдельным листам — прекрасно
работает прямо с шары.

**Типы аннотаций:**

- `DOCUMENT_FIELD` (17 167 / 24 686) — поля **основной надписи**: `META-DOC-CODE`, `META-SHEET`,
  `META-REVISION`, `META-DATE`, `META-MARK`. Готовая выборка для извлечения штампа.
- `MATRIX_FIELD` (13 119 / 16 263) — кандидаты значений параметров, код = код организатора
  (`PZ-002`, `KR-055`…).
- `CONFIRMED_VIOLATION_EVIDENCE` (20) и `SECOND_REVIEW_CHECK` (12 / 11) — единственные записи,
  связанные с `check_id`.

**Важно про качество.** Статус 99.9 % аннотаций — `AUTO_FIELD_CANDIDATE`
(`annotation_status: MACHINE_ASSISTED_PREANNOTATION_NEEDS_EXPERT_ACCEPTANCE`, confidence 0.6…1.0,
медиана 0.82). Это **машинная предразметка по ключевым словам, а не эталон**: встречаются явные
ложные срабатывания (слово «специалистов» размечено как «Спецификация МАФ»). Как метки значений
их брать нельзя — только как подсказку, где искать. Настоящий эталон — `*_gold_checks.jsonl`
и `finding_groups.jsonl`.

**Геометрия аннотаций:** `bbox_normalized = bbox_pdf / (page_width, page_height)`, начало
координат **в левом нижнем углу**, как в самом PDF. У нас (PyMuPDF, pdf.js) — в левом верхнем, поэтому
ось y при сравнении переворачивается (`eval.cv.top_left`). Исправлено 25.09: раньше здесь стояло
«в левом верхнем углу», а на обучающей части из 60 полей штампа 58 совпадают с нашим текстом только
перевёрнутыми. Медианная площадь bbox —
0.00065 страницы (отдельные слова), p90 — 0.014.
В пилотных файлах встречаются два других формата: `rects_normalized_xyxy_top_origin`
(нормализовано, верхний левый угол) и `bbox_pdf_bottom_left` (пункты, нижний левый угол,
с пометкой `after_rotation_normalization`) — при импорте разметки приводим к одному виду.

## 4. Эталон и правила оценки

`02_…/hackathon_gold_20260811/` содержит эталон и правила оценки.

**Схема ответа участника** (`submission_schema.json`):

```jsonc
{ "object_id": "...", "checks": [{
  "parameter_code": "KR-055",          // код организатора, не M-055
  "location": "Фундаментная плита",    // это наш rule_key
  "pd_value": null, "rd_value": null, "id_value": null,
  "violation_label": "VIOLATION_PRESENT | NO_VIOLATION | MISSING_DOCUMENT | COMPARISON_IMPOSSIBLE",
  "protocol_status": "OK | WARNING | CRITICAL | ID_MISSING | RD_MISSING | PD_MISSING | COMPARISON_IMPOSSIBLE",
  "criticality": "...",
  "evidence": [{ "stage": "PD", "file_id": "F0171", "pdf_page_number": 104 }]  // страница, не bbox
}]}
```

**Веса оценки** (`scoring_config.json`, статус `PILOT_SCORING_PROPOSAL`):

| Что | Баллов |
|---|---:|
| F1 выявления расхождений | **60** |
| Локализация источника — точные файл и страница | 15 |
| Нормализованное значение и статус | 15 |
| Целостность комплекта и работа со сплитами | 10 |

- Ключ сопоставления атомарной точки: **`object_id` + `parameter_code` + `location`**
  (у нас — `param_code` + `rule_key`);
- разрешён групповой ответ, если он покрывает все `location` одной `finding_group_id`;
- **при пропуске любой утверждённой критической точки итог ограничен 59 из 100**;
- отрицательные проверки входят в precision, `UNREVIEWED` отрицательным классом не считается;
- в зачёт идут только записи с `score_eligible = true`.

**Масштаб эталона** (`dataset_card.json`, `validation_report.json`): 19 атомарных проверок
(11 позитивных, 8 отрицательных), 5 `finding_groups`, покрыто **9 из 132 параметров**,
43 связи доказательств. В скрытой части — всего **4 атомарные точки**; организаторы сами пишут,
что для устойчивого рейтинга этого мало и набор будут расширять.

## 5. Коды параметров

Каталог организаторов использует коды вида `<РАЗДЕЛ>-<NNN>`: `PZ` 23, `SPZU` 16, `AR` 14, `KR` 14,
`PPM` 13, `POS` 9, `ODI` 9, `POD` 8, `ZU` 8, `IOS1…IOS5` 13, `OOS` 4, `SM` 1.

Проверено программно: **числовой суффикс кода = `parameter_id`, и все 132 наименования совпадают
с нашей матрицей**, то есть `M-0NN ↔ <РАЗДЕЛ>-0NN` — соответствие взаимно однозначное.
Готовая таблица: [parameter-code-map.csv](parameter-code-map.csv).
Наружу (в выгрузку для организаторов) нужно отдавать **их** код, внутри можно оставить `M-xxx`.

## 8. Что из этого следует для ML-конвейера

1. **OCR — не «потом», а критический путь.** 55 % страниц скрытой части без текста; базовый OCR
   нужен раньше тонкой работы с таблицами.
2. **Оценка идёт по странице, а не по bbox.** 15 баллов даёт точное попадание «файл + страница».
   bbox оставляем (он нужен инспектору в UI и нашим метрикам), но приоритет — не потерять страницу.
3. **`location` — это помещение или конструктивный элемент**, ровно наш `rule_key`: для M-002 —
   номера помещений из экспликации, для M-055 — элементы из спецификации.
4. **Свободный поиск обязателен** (`FREE-*` в зачётных точках): на одной матрице 60 баллов F1 не собрать.
5. **Штамп можно извлекать по разметке:** 41 тысяча аннотаций `META-*` с bbox — материал и для
   правил, и для обучаемого детектора полей.
6. **Дубликаты и редакции — это 10 баллов «целостности»**: sha256, `duplicate_group`, связи ИД ↔ РД.
7. **Предразметку `MATRIX_FIELD` нельзя брать за истину** — только как подсказку, где искать.
8. **Производительность:** 52 тысячи страниц, файлы до 969 страниц, ИД по 5 ГБ. Нужны кеш по
   sha256, постраничный параллелизм и бюджет OCR (по требованию, а не сплошной).

## 9. Как воспроизвести

Скрипты разбора лежат вне репозитория (данные тяжёлые). Порядок:

1. инвентаризация `dataset/` (`os.walk`, длинные пути) — список файлов с размерами;
2. чтение `data/*.jsonl` обоих сплитов — агрегаты по стадиям, страницам, аннотациям;
3. скан PDF через PyMuPDF с выборкой до 12 страниц на файл — поворот, CropBox, текст, растр, OCG;
4. сверка `document_manifest.jsonl` с корпусом: **416 из 416 путей совпали**, перекодировка имён
   этой выгрузке не нужна (в отличие от прошлой).

Планируется перенести это в команду `inspector-ml dataset scan`, чтобы отчёт собирался одной командой.

## 10. Чего трогать не стоит

В выгрузке присутствуют закрытые материалы организатора, помеченные `do_not_release`
(`hackathon_gold_20260811/ОРГАНИЗАТОР_ЗАКРЫТЫЙ/`, `hidden_gold_checks_organizer_only.jsonl`,
`review_queue.jsonl`, `evidence_index.jsonl` для скрытой части). Их **не используем ни для обучения, ни для подбора порогов**,
чтобы метрики на скрытой части остались честными.
